This document lists all files created and their purposes.

==============================================================================
DATABASE MODELS (2 files)
==============================================================================

1. models/MatchRequest.ts
   Purpose: Stores user search requests for peer interviews
   Key fields:
   - userId: User searching for a match
   - role: Interview role (Backend, Frontend, etc.)
   - level: beginner, intermediate, advanced
   - slot: Desired interview time
   - status: searching → matched → cancelled/completed
   
   Used in: Batch matcher, request creation

2. models/InterviewSession.ts
   Purpose: Stores matched interview sessions between two users
   Key fields:
   - user1Id, user2Id: Matched users
   - confirmationDeadline: 10-minute confirmation window
   - meetLink: Google Meet link (created after confirmation)
   - status: pending_confirmation → confirmed → in_progress → completed
   - user1Rating, user2Rating: Post-interview ratings (1-5 stars)
   
   Used in: Confirmation, ready check, rating submission

==============================================================================
UTILITY LIBRARIES (4 files)
==============================================================================

1. lib/googleCalendar.ts
   Purpose: Google Calendar API integration for Meet links
   Functions:
   - createGoogleCalendarEvent(): Creates calendar event + generates Meet link
   - updateCalendarEvent(): Updates event status
   - cancelCalendarEvent(): Deletes event and sends cancellation
   
   Used in: Confirmation flow (STEP 6A)
   Credentials needed: Google Service Account

2. lib/resend.ts
   Purpose: Email notifications via Resend
   Functions:
   - sendConfirmationRequest(): "Match found, confirm in 10 mins"
   - sendReadyCheckReminder(): "Interview starts in 10 mins, are you ready?"
   - sendInterviewReminder(): 30-min and 5-min reminders with Meet link
   - sendPostInterviewRating(): "Please rate your interview"
   
   Used in: Batch matcher, confirmation, ready check, completion
   API key: re_C3SJ7WXq_KG627NqsZUd44AHt4s2GXQCn

3. lib/batchMatcher.ts
   Purpose: Finds compatible users and creates matches
   Functions:
   - runBatchMatcher(): Groups requests by role/level/slot, creates sessions
   
   Process:
   1. Find all "searching" requests
   2. Group by role, level, slot
   3. For each group with 2+ users:
      - Create InterviewSession
      - Send confirmation emails
      - Update statuses
   
   Runs: Every 2-5 minutes via cron job

4. lib/reminderNotifications.ts
   Purpose: Scheduled reminder emails
   Functions:
   - sendReminderNotifications(): Sends 30-min and 5-min reminders
   - sendPostInterviewSurveys(): Sends rating request emails
   
   Used in: Scheduled tasks (optional cron job)

==============================================================================
API ROUTES (7 files)
==============================================================================

1. app/api/peer-interview/request/route.ts
   Methods: POST, GET
   - POST: Create MatchRequest (STEP 1-2)
   - GET: Retrieve user's active requests
   
   Example:
   POST /api/peer-interview/request
   { role: "Backend", level: "intermediate", slot: "2024-05-20T14:00:00Z" }

2. app/api/peer-interview/matcher/route.ts
   Method: GET
   Purpose: Batch matcher endpoint (STEP 3)
   Call: Every 2-5 minutes from cron job
   Header: Authorization: Bearer CRON_SECRET
   
   Process:
   1. Find matching requests
   2. Create InterviewSessions
   3. Send confirmation emails

3. app/api/peer-interview/confirm/route.ts
   Method: GET
   Purpose: Handle confirmation requests (STEP 5-6)
   Query: ?sessionId=...&userId=...&action=accept|decline
   
   If both confirm:
   - Creates Google Calendar event
   - Generates Meet link
   - Sends calendar invites
   Status: pending_confirmation → confirmed

4. app/api/peer-interview/ready/route.ts
   Method: POST
   Purpose: Handle ready checks (STEP 11-12)
   Body: { sessionId, ready: true|false }
   
   If both ready:
   Status: confirmed → in_progress
   If one declines:
   Status: confirmed → cancelled

5. app/api/peer-interview/complete/route.ts
   Method: POST
   Purpose: Submit post-interview ratings (STEP 13-14)
   Body: { sessionId, punctuality, communication, usefulness, feedback }
   
   Process:
   1. Store rating
   2. If both rated: award credits
   3. Update status: in_progress → completed

6. app/api/peer-interview/sessions/route.ts
   Method: GET
   Purpose: Get all user's interview sessions
   Returns: Array of sessions (active + completed)

7. app/api/peer-interview/session/[id]/route.ts
   Method: GET
   Purpose: Get specific session details
   Returns: Full session object with all details

FLOW SUMMARY (WHAT HAPPENS WHEN)
==============================================================================

Timeline:

1. USER CREATES REQUEST
   → POST /api/peer-interview/request
   → MatchRequest created (status=searching)

2. EVERY 2-5 MINUTES
   → Batch matcher runs
   → Groups compatible requests
   → If 2+ compatible: create InterviewSession
   → Send confirmation emails

3. USER CONFIRMS (within 10 mins)
   → GET /api/peer-interview/confirm?action=accept
   → If both confirm:
     * Create Google Calendar event
     * Generate Meet link
     * Status → confirmed

4. ONE DECLINES or TIMEOUT
   → Status → cancelled
   → Other user back to queue

5. 10 MINS BEFORE INTERVIEW
   → Ready check email sent
   → User clicks "I'm Ready"
   → Status → in_progress

6. INTERVIEW HAPPENS
   → Users join Google Meet

7. AFTER INTERVIEW
   → Rating email sent
   → User submits 5-star ratings
   → Credits awarded
   → Status → completed

==============================================================================
KEY DESIGN DECISIONS
==============================================================================

1. No immediate Meet link creation
   - Saves API quota
   - Only creates after BOTH confirm
   - Prevents wasted links

2. 10-minute confirmation window
   - Gives users time to see email
   - Prevents abandoned bookings
   - Auto-cancels after timeout

3. Ready check 10 mins before
   - Last-minute verification
   - Catches last-minute cancellations
   - Improves no-show rate

4. Post-interview rating required
   - Only way to get credits
   - Ensures accountability
   - Builds reputation system

5. Email-based confirmation
   - No app notification needed
   - Works for all users
   - Calendar integration is powerful
