STEP 2: DATABASE MODELS
==============================================================================

Two new MongoDB models have been created:

1. MatchRequest - Stores user search requests
   - userId: User ID searching for a match
   - role: Interview role (Backend, Frontend, DSA, etc.)
   - level: beginner, intermediate, advanced
   - slot: Scheduled interview time
   - status: searching, matched, cancelled, completed
   - createdAt: When request was created

2. InterviewSession - Stores matched interview sessions
   - user1Id, user2Id: IDs of matched users
   - role, level: Interview details
   - slot: Scheduled time
   - status: pending_confirmation → confirmed → in_progress → completed
   - confirmationDeadline: 10 minutes from match
   - meetLink: Google Meet link (created after both confirm)
   - calendarEventId: Google Calendar event ID
   - user1Confirmation, user2Confirmation: {confirmed, confirmedAt, ready, readyAt}
   - user1Rating, user2Rating: Post-interview ratings

==============================================================================
STEP 4: API ENDPOINTS OVERVIEW
==============================================================================

All endpoints are under /api/peer-interview/:

1. CREATE MATCH REQUEST
   POST /api/peer-interview/request
   Body: { role, level, slot }
   Returns: MatchRequest object

2. GET USER'S REQUESTS
   GET /api/peer-interview/request
   Returns: Array of user's MatchRequests

3. BATCH MATCHER (Run via cron)
   GET /api/peer-interview/matcher
   Headers: { Authorization: "Bearer CRON_SECRET" }
   Returns: { matched, errors }
   Purpose: Runs every 2-5 minutes to find and match compatible users

4. CONFIRMATION DIALOG
   GET /api/peer-interview/confirm
   Query: ?sessionId=...&userId=...&action=accept|decline
   Returns: Updated InterviewSession

5. READY CHECK
   POST /api/peer-interview/ready
   Body: { sessionId, ready: boolean }
   Returns: Updated InterviewSession

6. POST-INTERVIEW RATING
   POST /api/peer-interview/complete
   Body: { sessionId, punctuality, communication, usefulness, feedback }
   Returns: Updated InterviewSession with credits awarded

7. GET SESSION DETAILS
   GET /api/peer-interview/session/[id]
   Returns: Full InterviewSession details

STEP 5: SETTING UP BATCH MATCHER (CRON JOB)
==============================================================================

The batch matcher needs to run every 2-5 minutes. Choose one approach:

OPTION A: Using Vercel Cron (Recommended for production)
----------------------------------------------------
1. Create app/api/cron/matcher/route.ts:

import { NextRequest, NextResponse } from "next/server";
import { runBatchMatcher } from "@/lib/batchMatcher";

export async function GET(req: NextRequest) {
  try {
    const authHeader = req.headers.get("authorization");
    if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
      return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
    }

    const result = await runBatchMatcher();
    return NextResponse.json({ success: true, ...result });
  } catch (error) {
    console.error("[Matcher Cron Error]", error);
    return NextResponse.json({ error: "Server error" }, { status: 500 });
  }
}

2. In vercel.json (create if doesn't exist):

{
  "crons": [{
    "path": "/api/cron/matcher",
    "schedule": "*/2 * * * *"
  }]
}

OPTION B: Using External Cron Service
--------------------------------------
Use services like:
- CRON-JOB.org (free)
- EasyCron
- AWS EventBridge

Configure to call:
GET https://yourdomain.com/api/peer-interview/matcher
Header: Authorization: Bearer YOUR_CRON_SECRET

Every 2-5 minutes.

OPTION C: Self-hosted Node.js Cron
-----------------------------------
Create a separate cron service:

import cron from "node-cron";
import { runBatchMatcher } from "./lib/batchMatcher";

// Run every 2 minutes
cron.schedule("*/2 * * * *", async () => {
  console.log("Running batch matcher...");
  await runBatchMatcher();
});

STEP 6: NOTIFICATION FLOW
==============================================================================

The system sends emails at critical points:

1. MATCH FOUND (10 mins to confirm)
   - Both users receive confirmation request
   - Email has Accept/Decline buttons
   - Auto-cancels if not confirmed in 10 minutes

2. READY CHECK (10 mins before interview)
   - Both users get "Are you ready?" prompt
   - Can confirm or cancel
   - If one cancels, session is terminated

3. REMINDERS
   - 30 minutes before: "Starting in 30 mins"
   - 5 minutes before: "Starting in 5 mins" + Meet link

4. POST-INTERVIEW
   - Email asking for rating
   - 1-5 star ratings on punctuality, communication, usefulness

STEP 9: CREDIT SYSTEM (Optional but Recommended)
==============================================================================

Credits are awarded based on:
- Base: 10 credits for completing interview
- Bonus: +5 credits if average rating >= 4.5 (excellent)
- Bonus: +3 credits if average rating >= 4.0 (good)

Penalties:
- No-show: -5 credits
- Late: -2 credits
- Decline after confirming: -3 credits

Implement in User model:
- credits: Running credit balance
- reliability: Score based on completion rate
- noShowCount: Track no-shows

==============================================================================
STEP 10: ERROR HANDLING & EDGE CASES
==============================================================================

Handled scenarios:

1. Confirmation Timeout
   - After 10 mins, if not both confirmed, session cancelled
   - Other user returned to queue
   - No Meet link created (saves API quota)

2. Ready Check Timeout
   - If user doesn't respond in 10 mins, session proceeds
   - If one cancels at ready check, session is cancelled

3. No-Show
   - User joins late/doesn't show
   - Can be marked and penalty applied
   - Affects reliability score

4. User Declines After Match
   - Session cancelled immediately
   - Other user put back in queue
   - Can continue searching

5. Google Calendar Failure
   - Session still confirmed even if Calendar fails
   - Meet link generated later or provided via email
   - Graceful degradation

SUPPORT & TROUBLESHOOTING
==============================================================================

Common Issues:

1. Matches not being created
   - Check if CRON_SECRET is set and matching
   - Verify batch matcher is being called
   - Check logs for errors in batchMatcher.ts

2. Google Calendar events not created
   - Verify service account credentials in .env
   - Check Google Cloud project permissions
   - Ensure Calendar API is enabled

3. Emails not sending
   - Verify RESEND_API_KEY is correct
   - Check Resend dashboard for delivery status
   - Check spam folder

4. Confirmation links not working
   - Verify NEXTAUTH_URL is correct
   - Check if email links are being opened (tracking)
   - Ensure session IDs match

5. Ready check dialog not showing
   - Verify component is being rendered
   - Check if session exists in database
   - Check browser console for errors
