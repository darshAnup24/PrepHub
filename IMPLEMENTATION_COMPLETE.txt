ARCHITECTURE OVERVIEW
==============================================================================

USER FLOW:
  1. User clicks "Connect Google Calendar"
     → Redirects to Google OAuth consent screen
     → User approves
     → Tokens stored securely

  2. Two users confirm interview match
     → Calls generateMeetLink()
     → Creates Google Calendar event
     → Meet link auto-generated
     → Job queue schedules reminders:
        - 30 mins before
        - 5 mins before
        - 10 mins before (ready check)
        - 15 mins after (auto-cancel)

  3. At scheduled time, Upstash calls endpoints:
     → /api/jobs/reminder (send email)
     → /api/jobs/ready-check (trigger notification)
     → /api/jobs/auto-cancel (check for no-show)

  4. Tokens refresh automatically:
     → Before using Google API
     → If expired, use refreshToken
     → Get new accessToken
     → Update database

WHAT HAPPENS STEP BY STEP
==============================================================================

Timeline of a successful interview:

T=0 mins
  - User 1: Connects Google Calendar (/api/auth/google)
  - Redirected to Google OAuth
  - Approves access
  - Tokens stored: accessToken, refreshToken, expiryDate

T=5 mins
  - User 1 & 2: Both create match requests
  - Status: "searching"

T=10 mins
  - Batch matcher finds both users
  - Creates InterviewSession
  - Status: "pending_confirmation"
  - Sends confirmation emails

T=12 mins
  - User 1: Clicks "Accept" link
  - User 1Confirmation.confirmed = true
  - Waiting for User 2

T=14 mins
  - User 2: Clicks "Accept" link
  - User 2Confirmation.confirmed = true
  - Both confirmed!

T=14:30 mins
  - System calls: generateMeetLink()
  - OAuth token checked: not expired, so use as-is
  - Creates Google Calendar event
  - Gets Meet link from conferenceData
  - Stores in database: googleMeetLink
  - Status: "confirmed"
  - Schedules jobs via QStash:
    ├─ 30-min reminder (T+330 = 345)
    ├─ 5-min reminder (T+355)
    ├─ Ready check (T+350)
    └─ Auto-cancel (T+375)

T+330 mins (before scheduled time)
  - QStash triggers: /api/jobs/reminder
  - Sends "Interview in 30 mins" email to both

T+350 mins (before scheduled time)
  - QStash triggers: /api/jobs/ready-check
  - Shows "Are you ready?" dialog

T+355 mins (before scheduled time)
  - QStash triggers: /api/jobs/reminder
  - Sends "Interview in 5 mins" email + Meet link

T+360 mins (scheduled time)
  - Interview starts
  - Both join Google Meet

T+375 mins (15 mins after start)
  - QStash triggers: /api/jobs/auto-cancel
  - If users haven't joined: Mark as no-show
  - Otherwise: Continue normally

T+420 mins (after 1 hour)
  - Interview ends
  - System sends: "Rate your interview" email

T+425 mins (5 mins after)
  - User 1: Clicks rating link
  - Submits ratings: punctuality(5), communication(5), usefulness(5)
  - Credits awarded: 10 + 5 bonus = 15 credits

T+430 mins (10 mins after)
  - User 2: Clicks rating link
  - Submits same ratings
  - Credits awarded
  - Session status: "completed"

TROUBLESHOOTING QUICK REFERENCE
==============================================================================

Problem: "Calendar event not created"
Check: GOOGLE credentials, Calendar API enabled, service account permissions

Problem: "Jobs not executing"
Check: QStash token, deployed to Vercel, endpoint URLs correct

Problem: "Tokens not refreshing"
Check: refreshToken stored, expiry date set, client secret correct

Problem: "Emails not sent"
Check: RESEND_API_KEY, endpoint exists, Resend dashboard

Problem: "OAuth redirect loop"
Check: GOOGLE_CLIENT_ID/SECRET correct, redirect URI matches

Solution: Most issues? Check .env and Vercel environment variables!
